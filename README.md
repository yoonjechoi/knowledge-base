# knowledge-base

내 지식베이스를 Claude Code 플러그인으로 다뤄요. 카파시 LLM Wiki 방식이에요. `raw/` 원자료를 AI가 `wiki/` 정리 노트로 쌓아 갑니다.

AI가 자료를 읽고 정리한 글 한 편을 **노트**라고 불러요. 노트는 `wiki/` 안의 주제별 **폴더**에 쌓여요.

스킬은 `kb` 하나예요.

| 작업 | 이렇게 말해요 |
|---|---|
| 처음 만들기 | 「지식베이스 만들어 줘」 |
| 넣기 | 「지식베이스에 넣어 줘」, 「이 결론 저장해 줘」 |
| 정리 | 「바로 정리해 줘」, 「대기 자료 정리해 줘」 |
| 찾기 | 「지식베이스에서 찾아 줘」, 「예전에 이거 어떻게 했지」 |
| 점검 | 「지식베이스 점검해」 |

- **넣기는 수 초면 끝나요.** 바깥 자료는 `raw/` 에 저장하고 대기 목록에 요약 한 줄을 적어요. 정리되기 전에도 찾기로 찾을 수 있어요(PDF, 사진도 요약으로).
- **정리는 뒤에서 해요.** 대기 자료로 `wiki/` 노트를 고치거나 만들어요. 「바로 정리해 줘」라고 하면 `tidier` 에이전트가 대화를 막지 않고 뒷단에서 돌아요. 중간에 멈추면 남은 항목은 다음에 이어서 해요.
- **결론은 바로 들어가요.** 대화나 기존 노트에서 나온 결론은 `raw/` 를 거치지 않고 `wiki/synthesis/` 로 가요.
- **점검은 정리 직후 돌아요.** 깨진 링크처럼 기계적인 것만 고치고, 내용이 어긋나는 것은 표시만 해서 사람이 판단해요.

## 매일 밤 정리하기

클로드 데스크톱 앱 「예약」에 만들어요. 폴더는 지식베이스 폴더, 권한은 권한 무시, 실행은 이 컴퓨터에서만으로 정해요.

```
/knowledge-base:kb 대기 자료 일괄 정리
```

- 예약 시각에 컴퓨터와 앱이 켜져 있어야 돌아요. 못 돈 날의 자료는 대기에 남아 다음에 정리돼요.
- 정리는 AI 작업이라 대기 자료가 많으면 시간과 사용량이 그만큼 들어요.
- 대기가 없는 밤에도 점검은 돌고 `log.md` 에 한 줄이 남아요.
- 대기가 없어도 60줄을 넘는 대표 노트는 나눠요. 한 번에 3개까지예요. 넘는 노트가 없으면 노트를 열지 않아요.

## 설치

Claude Code 에서:

```
/plugin marketplace add yoonjechoi/knowledge-base
/plugin install knowledge-base@knowledge-base
```

그다음 「지식베이스 만들어 줘」라고 하면 기본 `~/knowledge-base`(윈도우 `C:\Users\내이름\knowledge-base`)에 폴더가 생겨요. 다른 곳에 두려면 「○○ 폴더에 지식베이스 만들어 줘」.

## 업데이트

터미널에서:

```
claude plugin marketplace update knowledge-base
claude plugin update knowledge-base@knowledge-base
```

떠 있는 세션은 옛 판을 계속 써요. 그 세션에서 `/reload-plugins` 를 치거나 다시 시작하면 새 판이 적용돼요. 내 지식베이스 폴더와 `rules.md` 는 바뀌지 않아요.

## 내 지식베이스에 있는 것

```
~/knowledge-base/
├── rules.md    규칙. 내 맘대로 고쳐요. 플러그인을 업데이트해도 안 바뀌어요
├── raw/        원자료. AI가 읽기만 해요
└── wiki/       정리 노트. AI가 써요
    ├── index.md · log.md · inbox.md(정리 대기 목록)
    └── me · business · brands · customers · projects · topics · synthesis …
```

- **규칙:** 지식베이스의 `rules.md` 가 있으면 그것만 쓰고, 없으면 플러그인의 기본 규칙을 써요. 내 `rules.md` 를 쓰면 기본 규칙이 나중에 좋아져도 자동으로 따라오지 않아요.
- **기본 규칙 받기:** 「기본 규칙에서 달라진 내용을 내 rules.md 와 비교해 줘」라고 하면 AI가 차이를 보여 주고, 고를 내용만 넣어 줘요.
- **폴더:** `wiki/` 안의 폴더가 곧 분류예요. 앞으로도 쌓일 종류의 자료가 생기면 맞는 폴더를 만들고 `index.md` 에 머리 한 줄을 더해요. 한 번뿐인 자료는 `topics/` 에 둬요. 플러그인을 고칠 일이 없어요.
- **프로젝트:** 프로젝트 하나가 폴더 하나예요. 대표 노트에는 현황 요약과 노트 목록만 두고, 내용이 길어지거나 따로 찾을 만하면 새 노트로 빼요. `index.md` 에는 대표 노트만 올려요.
- **대표 노트 길이:** 대략 60줄까지예요. 넘으면 점검이 알려 주고, 정리가 긴 묶음을 같은 폴더의 새 노트로 옮겨요. 내용은 지우지 않아요. 쪼개기 어려운 노트는 그대로 두고 알려 줘요.
- **찾는 순서:** `index.md`, 폴더의 파일 이름, 대표 노트, 해당 노트 순서로 내려가요. 전체를 읽지 않아도 돼요.
- **링크:** 옵시디언에서 깔끔하게 보이도록 `[[파일-이름|보일 이름]]` 모양으로 써요. 점검이 어긋난 링크를 고쳐 줘요.
- **위치:** `~/.config/knowledge-base/config.json` 의 `kb` 한 줄이에요.

## 기본 규칙

AI는 어떤 작업이든 먼저 규칙을 읽어요. 전체는 `rules.md` 에 있고, 핵심은 이래요.

- **원자료는 건드리지 않아요.** `raw/` 가 사실의 원본이에요. 고치지도 지우지도 않아요. 내용을 바로잡을 때도 고칠 말을 새 자료로 넣어요.
- **노트는 AI가 써요.** `wiki/` 는 사람이 직접 고치지 않아도 돼요. 새 자료가 오면 있는 노트를 고치고, 없으면 만들어요.
- **폴더마다 쌓는 모양이 달라요.** 고객 한 명, 결론 하나가 각각 노트 하나예요. 프로젝트와 브랜드는 하나가 폴더 하나예요. 날짜별로 쌓는 폴더는 하루가 파일 하나예요.
- **사실에는 출처를 붙여요.** 어느 원자료나 노트에서 왔는지 적어요. 정해지지 않은 일은 「검토 중」이라고 써요.
- **어긋나면 지우지 않아요.** 새 자료가 옛 내용과 다르면 `> 어긋남:` 으로 둘 다 남겨서 사람이 판단해요.
- **일정은 캘린더가 우선이에요.** 노트와 캘린더가 다르면 캘린더를 따르고 노트에 표시해요.
- **이름을 맞춰요.** 폴더는 영어, 내용은 한국어, 파일 이름은 띄어쓰기 대신 하이픈이에요. 노트 이름은 폴더가 달라도 겹치면 안 돼서 「회의록」 대신 `겨울-메뉴-회의록` 처럼 구체적으로 지어요. 실제로 이어지는 노트끼리만 링크해요.
- **지키는 선이 있어요.** 비밀번호, 카드, 계좌, 주민번호는 적지 않아요. 보내기, 게시, 결제, 삭제처럼 되돌릴 수 없는 일은 먼저 물어요.

## 응용해서 쓰기

규칙을 내 일에 맞게 바꾸면 쓰임이 넓어져요. 코드는 고치지 않아요. AI에게 말만 하면 돼요.

| 하고 싶은 일 | 이렇게 말해요 |
|---|---|
| 요리 레시피 모으기 | 「레시피 폴더를 만들어 줘. 요리 하나가 노트 하나야」 |
| 회의록 쌓기 | 「meetings 폴더를 만들어 줘. 하루가 파일 하나고, 정한 것과 할 일을 꼭 적어 줘」 |
| 아이 성장 기록 | 「아이 기록 폴더를 만들어 줘. 사진은 raw 에 두고 날짜별로 쌓아 줘」 |
| 독서 노트 | 「책 폴더를 만들어 줘. 노트마다 저자, 인상 깊은 문장, 내 생각을 넣어 줘」 |
| 안 쓰는 폴더 빼기 | 「브랜드 폴더는 안 써. 규칙에서 빼 줘」 |
| 내 방식 더하기 | 「노트 맨 위에 세 줄 요약을 넣는 규칙을 추가해 줘」 |
| 지키는 선 더하기 | 「고객 전화번호는 적지 않는 규칙을 추가해 줘」 |

폴더의 모양이나 규칙을 바꾸는 말은 `rules.md` 에 남아요. 이 파일이 없다면 먼저 만들어 달라고 하세요. 다음부터는 어느 대화에서든 같은 규칙으로 돌아가요.

## 다른 플러그인에서 쓰기

지식베이스를 쓰는 플러그인은 `knowledge-base:kb` 스킬만 불러요. 호출 방법은 [kb 스킬의 「다른 플러그인에서 부를 때」](plugins/knowledge-base/skills/kb/SKILL.md)에 있어요.

- 지식베이스 폴더, 설정, kb 스크립트를 직접 쓰지 않아요. 위치는 kb 만 알아요.
- 노트 틀은 부르는 플러그인이 갖고 있다가 넘겨요.
- 의존은 한 방향이에요. `plugin.json` 에 `dependencies` 로 knowledge-base 를 적어요. 마켓플레이스가 다르면 자기 `marketplace.json` 의 `allowCrossMarketplaceDependenciesOn` 도 필요해요.

## 필요한 것

- Claude Code
- 파이썬 3.9 이상 (윈도우는 `python` 또는 `py` 로 불러도 돼요)
- git. 있으면 지식베이스 바뀐 기록이 남아요. 없어도 쓸 수 있어요
