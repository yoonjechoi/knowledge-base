# ingest — 넣기

> `<스킬 폴더>` = 이 스킬을 불렀을 때 받은 Base directory. 도우미는 `python3 <스킬 폴더>/../../scripts/wiki.py`(윈도우에서 `python3` 이 없으면 `python`, 그것도 없으면 `py -3`).
> **먼저** `wiki.py where` 로 위치를 보고, 지식베이스가 없으면 setup 스킬부터 한다. 있으면 지식베이스 폴더의 `CLAUDE.md`(schema)를 읽고 따른다 — 폴더 · 페이지 모양 · 이 사람의 방식이 거기 있다. 사람에게는 「지식베이스」라고 한다.

원자료 하나가 들어오면 LLM 이 읽고, 요약 페이지를 쓰고, index 를 고치고, 관련된 개체 · 개념 페이지를 여러 개(보통 10~15개) 고치고, log 에 남긴다. 사람의 일은 좋은 자료를 고르고 무엇이 중요한지 정하는 것, LLM 의 일은 나머지 장부 정리 전부다.

**어느 방식으로 하나**
| 상황 | 방식 | 실행 |
|---|---|---|
| 자료 하나(또는 몇 개)를 사람과 대화 중에 넣음 | **함께 넣기** — 핵심을 이야기하고 쓴다 | 이 대화에서 |
| 「밀린 자료 다 넣어 줘」 · 「알아서 넣어 줘」 · 「대기 자료 (일괄) 정리」 · 여러 개를 한꺼번에 · schema 의 「내 방식」이 알아서 넣기 | **일괄 넣기** — 덜 지켜보며 | `Agent` 로 `knowledge-base:batch-ingester` 를 **백그라운드로**(`run_in_background: true`). `model` 은 넘기지 않는다 — 쓰는 사람의 기본 설정 모델로 돌게 |
| 내가 이미 에이전트 · 예약 실행이거나 사람이 없음 | 일괄 넣기 | 그 자리에서 아래 순서를 2번(이야기) 없이 |

## 1. 원자료를 raw/ 에 둔다

- 사람이 이미 `raw/` 에 넣었으면 그 파일을 쓴다.
- 파일 · 사진 · PDF 를 주면 `raw/` 로 복사한다(그림은 `raw/assets/`). 붙여 넣은 글 · 대화 내용은 `raw/YYYY-MM-DD-제목.md` 로 저장한다. 링크면 내용을 받아 마크다운으로 저장하고 맨 위에 원래 주소를 적는다.
- 파일 이름에는 `\ / : * ? " < > |` 를 쓰지 않고(윈도우에서 파일이 안 만들어진다) 하이픈으로 바꾼다. 이름 끝에 점 · 띄어쓰기도 두지 않는다. 제목에 그런 글자가 있어도 파일 이름에서만 바꾸고, 페이지 제목(`#`)은 원래대로 둔다.
- 이름이 겹치면 덮어쓰지 않고 `-2` 를 붙인다. **raw 의 파일은 그 뒤로 고치지 않는다.** 바로잡을 말이 있으면 그 말도 새 원자료로 넣는다.

## 2. 읽고, 핵심을 이야기한다 (함께 넣기)

원자료를 끝까지 읽는다(그림이 든 글이면 글을 먼저 읽고 그림을 따로 본다). 그리고 사람에게 짧게:
- 핵심 3~5개 — 이미 지식베이스에 있는 것과 무엇이 새롭고 무엇이 어긋나는지 함께
- 「무엇을 강조할까요? 이대로 쓸까요?」

`wiki/index.md` 를 먼저 읽어 두면 「무엇이 새롭나」를 말할 수 있다. 사람의 답(강조할 것 · 뺄 것)을 3번에 반영한다. 사람이 「알아서」라고 하면 바로 쓴다.

## 3. 페이지를 쓴다

1. **원자료 요약 페이지** `wiki/sources/제목.md` — 머리의 `sources` 에 그 원자료 경로 하나. 본문: 무엇에 관한 자료인지 · 핵심 주장 · 숫자와 날짜 · 나오는 개체와 개념 링크.
2. **개체 · 개념 페이지** — 원자료에 나오는 사람 · 회사 · 제품 · 장소와 개념마다, 있으면 **고치고** 없으면 **만든다**. 새 사실에는 근거 `[[sources/제목]]` 을 붙이고, 머리의 `sources` · `updated` 를 고친다. 옛 주장과 어긋나면 지우지 않고 `> 어긋남:` 으로 둘 다 남긴다.
3. **잇기** — 실제로 이어지는 페이지끼리 `[[폴더/파일|보일 이름]]`. 이번에 만든 페이지가 외톨이가 되지 않게 한다.
4. **전체 개요** — 이 자료가 큰 그림을 바꾸면 `wiki/overview.md` 를 고친다.
5. **index** — 새 페이지를 종류별 머리 아래에 한 줄씩 더하고, 요약이 바뀐 페이지는 그 줄을 고친다.
6. **log** — `wiki/log.md` 맨 아래에 `## [오늘] ingest | 원자료 제목` 과 건드린 페이지 목록.
7. **커밋** — 바꾼 파일만: `git -C <지식베이스> add <원자료> <페이지들> wiki/index.md wiki/log.md` → `commit -m "ingest: 제목"`. `add -A` 는 쓰지 않는다(다른 세션이 쓰는 중일 수 있다). git 이 없으면 건너뛴다.

## 4. 보고

함께 넣기: 만든 페이지 · 고친 페이지(몇 개인지와 이름) · 사람이 볼 어긋남. 「고친 것을 보시고 다르게 강조할 게 있으면 말해 주세요」 한 줄.
일괄 넣기를 띄웠으면: 「뒤에서 넣을게요」 한 줄만 하고 대화를 이어 간다. 끝났다는 알림이 오면 넣은 자료 수 · 만든 · 고친 페이지 · 어긋남을 두세 줄로 전한다.

## 테스트 시나리오

- **정상(함께):** 「이 글 지식베이스에 넣어 줘」 + 붙여 넣은 글 → raw 에 저장 → 핵심 3~5개와 질문 → 「좋아」 → sources 요약 1 + 개체 · 개념 여러 개 + index + log → 커밋 1개.
- **정상(일괄):** raw 에 파일 3개를 넣고 「밀린 자료 다 넣어 줘」 → 「뒤에서 넣을게요」 → batch-ingester 가 `wiki.py pending` 의 3개를 차례로 → 알림 → 두세 줄 보고. `wiki.py pending` 이 「모두 ingest 됨」.
- **오류:** 읽을 수 없는 파일(깨진 PDF) → 그 파일은 건너뛰고 보고에 「못 읽음: 파일 · 이유」. raw 에서 지우지 않는다.
