# ai-secretary — AI 비서 진입점

**실행 모드:** 서브 에이전트 파이프라인. 일지 → 화면 → 브리핑이 차례로 이어지기만 하면 되고 서로 대화할 일이 없어서 팀은 만들지 않는다.

| 단계 | 누가 (이 플러그인의 에이전트) | 스킬 | 남는 것 |
|---|---|---|---|
| 1 | `journal-writer` | daily-journal (저장은 kb 넣기) | 날짜별 일지 · 정리 시각(`~/.config/knowledge-base/last-run.txt`) |
| 2 | 메인(아티팩트 도구가 있는 쪽) | journal-page | 일지 화면(같은 주소) |
| 3 | `briefer` 또는 메인 | morning-brief | 해 두면 좋은 일 · 알림 1건 |

## 0. 상황 보기
- 「일지만」 → 1단계. 「화면만」 → 2단계. 「브리핑만 다시」 → 3단계. 「둘 다 / 처음부터」 → 1 → 2 → 3.
- 날짜를 말하면 그 업무일만 다시(`/daily-journal 날짜`, 정리 시각은 안 옮김).

## 부르기
`Agent` 로 `subagent_type: "knowledge-base:journal-writer"` · `"knowledge-base:briefer"`, 프롬프트에 이번 범위. 화면 올리기(Artifact)는 메인에서 한다 — 서브 에이전트에는 Artifact 도구가 없을 수 있다.
작은 일이면 에이전트 없이 메인에서 스킬을 바로 따라도 된다(예약 작업이 그렇게 돈다).

## 에러
- 1단계 실패: 정리 시각을 옮기지 않는다(다음에 다시 모음). 3단계는 있는 일지로 한다.
- 알림 실패: 한 번 다시, 그래도 실패면 한 줄로 알리고 끝.
- 아티팩트 도구 없음: 올리기 건너뜀, html 경로만.

## 예약 작업 (클로드 데스크톱 앱 「예약」 — launchd · cron · 작업 스케줄러는 쓰지 않는다)
| 이름 | 명령 | 시간 | 폴더 | 권한 | 실행 위치 |
|---|---|---|---|---|---|
| 업무 일지 새벽 정리 | `/knowledge-base:daily-journal` | 매일 01:00 | 지식베이스 폴더 | 권한 무시 | 이 컴퓨터에서만 |
| 아침 브리핑 알림 | `/knowledge-base:morning-brief` | 매일 07:00 | 지식베이스 폴더 | 권한 무시 | 이 컴퓨터에서만 |

## 테스트 시나리오
- 정상: `/daily-journal` → 범위 안 세션으로 일지 내용을 만들어 kb 넣기로 지식베이스에 넣음(journal 노트 · 이어지는 고객 · 프로젝트 노트) → 화면 같은 주소 → 정리 시각 이동. `/morning-brief` → 해 두면 좋은 일 2~3개 저장 → 알림 1건(「휴대폰으로 보냈어요」) → 화면 갱신.
- 에러: 구독 이름이 아직 없으면 brief.py 가 「휴대폰 알림은 건너뜀」 → 브리핑은 화면에만, ntfy-setup 안내 한 줄. 구독 이름은 어디에도 안 찍힘.
- 이어서: 새 대화가 없으면 「대화 0줄」 → 저장 없이 정리 시각만, 일지 중복 없음.
