# query — 찾기

> `<스킬 폴더>` = 이 스킬을 불렀을 때 받은 Base directory. 도우미는 `python3 <스킬 폴더>/../../scripts/wiki.py`(윈도우에서 `python3` 이 없으면 `python`, 그것도 없으면 `py -3`).
> **먼저** `wiki.py where` 로 위치를 보고, 지식베이스가 없으면 그렇다고 말하고 setup 을 권한다. 있으면 지식베이스 폴더의 `CLAUDE.md`(schema)를 읽고 따른다. 사람에게는 「지식베이스」라고 한다.

**결론을 받아 저장만 해 달라는 요청**(다른 플러그인 · 사람이 결론 · 근거 · 날짜를 주며 「이 결론 저장해 줘」)이면 1~3번을 건너뛰고 4번의 저장을 묻지 않고 한 뒤 5번으로 간다. 같은 결론 페이지가 `wiki/analyses/` 에 이미 있으면 새로 만들지 않고 그 페이지를 고친다.

1. **`wiki/index.md` 를 먼저 읽고** 걸리는 페이지를 고른다. index 만으로 수백 페이지까지 충분하다. 모자라면 `grep -ril` 로 `wiki/` 를 더 찾는다.
2. 고른 페이지를 읽는다. 페이지가 가리키는 `[[링크]]` 중 질문에 걸리는 것은 따라가 읽는다. 페이지에 없는 세부가 필요하면 그 페이지의 `sources` 원자료까지 내려간다.
3. **근거를 붙여 종합해 답한다.** 근거는 `[[페이지]]` 또는 원자료 경로. 질문에 맞는 모양으로 낸다 — 글, 비교표, 슬라이드(Marp 마크다운), 차트(matplotlib 그림), 옵시디언 캔버스. 지식베이스에 없으면 없다고 말하고, 무엇을 넣으면 답할 수 있는지 한 줄.
4. **좋은 답은 지식베이스에 남긴다.** 비교 · 분석 · 새로 찾은 연결처럼 다시 쓸 만한 답이면 「지식베이스에 저장할까요?」 한 줄로 묻는다(사람이 저장해 달라고 했으면 묻지 않는다). 예면:
   - `wiki/analyses/제목.md` 새 페이지 — 머리의 `type: analysis`, `sources` 에 근거 원자료. 본문은 질문 · 답 · 근거 링크 · 날짜. 슬라이드 · 차트로 냈으면 그 파일도 `wiki/analyses/` 에 두고 링크한다.
   - 근거 페이지들에 이 분석으로 가는 링크 한 줄, 큰 그림을 바꾸면 `wiki/overview.md` 도.
   - `wiki/index.md` 의 분석 머리 아래 한 줄.
   이렇게 해야 질문으로 찾아낸 것도 넣은 자료처럼 쌓인다.
5. **log** — `wiki/log.md` 맨 아래에 `## [오늘] query | 질문 한 줄`(저장했으면 만든 페이지도). 바꾼 파일만 커밋: `git -C <지식베이스> add <파일들>` → `commit -m "query: 질문"`. git 이 없으면 건너뛴다.
