# kb — 내 지식베이스

> `<이 스킬 폴더>` = 이 스킬을 불렀을 때 받은 Base directory.
> 명령의 `python3` 이 없다고 나오면(윈도우) `python` 으로, 그것도 없으면 `py -3` 으로 바꿔 친다.

**어떤 작업이든 먼저** `python3 <이 스킬 폴더>/scripts/settings.py show` 로 지식베이스 위치(`kb`)와 규칙 파일(`rules`)을 확인하고, **그 규칙 파일을 읽고 따른다.** 지식베이스 안에 `rules.md` 가 있으면 그것이 규칙이고, 없으면 이 스킬의 기본 규칙이다. 폴더 · 이름 · 링크 · 노트 모양 · 지키는 선이 다 거기 있다. 사람과 이야기할 때는 「위키」 대신 「지식베이스」.

동작은 카파시 LLM Wiki 와 같은 셋 — **ingest**(넣기) · **query**(찾기) · **lint**(점검) — 이고, 설치 뒤 처음 한 번 **setup** 을 한다. 지식베이스 폴더가 없으면 무엇을 부탁받든 setup 부터 한다.

| 사람이 하는 말 | 동작 |
|---|---|
| 「지식베이스 만들어 줘」 · 「지식베이스 설정해 줘」 · 설치 직후 · 지식베이스 폴더가 없을 때 | setup |
| 「지식베이스에 넣어 줘」 · 「이 파일 넣어 줘」 · 「이 결론 저장해 줘」 · 「다시 넣어 줘 · 고쳐 줘」 | ingest |
| 「바로 정리해 줘」 · 「대기 자료 정리해 줘」 · 「대기 자료 일괄 정리」 · 「지식베이스 정리해 줘」 | ingest 2단계만(대기 전부) |
| 「지식베이스에서 찾아 줘」 · 「예전에 ~ 어떻게 했지」 · 「○○ 고객 메모 보여 줘」 | query |
| 「지식베이스 점검해」 | lint |
| 다른 플러그인이 부를 때 | 맨 아래 「다른 플러그인에서 부를 때」 |

## setup — 설치 뒤 처음 한 번

1. `settings.py show` 의 `kb` 가 지식베이스 자리다. 사람이 있으면 「지식베이스를 ○○ 에 만들까요? 다른 곳을 원하면 말해 주세요」 한 줄로 묻는다(기본 `~/knowledge-base`, 윈도우는 `C:\Users\내이름\knowledge-base`). 그 폴더에 `rules.md` 와 `wiki/index.md` 가 이미 있으면 새로 만들지 않고 그대로 쓴다고 알린다. 다른 파일이 들어 있으면 알리고 다른 폴더를 권한다.
2. `python3 <이 스킬 폴더>/scripts/setup.py` — `rules.md` · `raw/` · `wiki/` 와 시작 폴더 · `index.md` · `log.md` · `inbox.md` 를 만들고, git 이 있으면 기록 저장소로 시작한다. 다른 곳이면 `setup.py <폴더>`(설정도 그 폴더로 바뀐다). 이미 있는 파일은 건드리지 않는다.
3. 만든 폴더 구조를 ├── └── 그림으로 보여 주고, 「이제 『지식베이스에 넣어 줘』로 자료를 넣으면 돼요」 한 줄.
4. 옵시디언으로 보고 싶다고 하면: 옵시디언에서 「폴더를 보관함으로 열기」로 지식베이스 폴더를 고르게 안내한다.

## ingest — 넣기 (대화를 막지 않는다)

두 단계다. **1단계 raw 저장은 지금 이 대화에서 수 초 만에 끝내고, 2단계 노트 쓰기는 뒷단 에이전트에 맡긴다.** 왜: 자료는 이 대화에만 있으니 먼저 raw 에 저장해야 잃지 않고, 노트 쓰기는 노트 여럿을 읽고 고치느라 몇 분 걸려 대화를 막기 때문이다. 바깥 자료 · 대화에서 나온 결론 · 고칠 말이 모두 같은 길로 들어간다.

### 1단계 raw 저장 — 지금, 수 초

넣을 자료가 없는 말(「대기 자료 정리해 줘」)이면 이 단계를 건너뛴다.

1. 자료를 훑어 **주제**와 **핵심 사실 한 줄**을 만든다. 글 · PDF · 사진을 직접 읽어 쓴다. 나중에 이 줄로 찾으므로 사람 · 장소 · 날짜 · 금액 같은 찾을 낱말을 넣는다(규칙이 적지 않게 한 값이 있으면 여기에도 적지 않는다). 긴 자료는 앞부분과 차례만 본다. 끝까지 읽는 것은 2단계가 한다.
2. 파일이면 `python3 <이 스킬 폴더>/scripts/inbox.py add --file <파일> --topic <주제> --facts <핵심 사실> --source <출처>`. 이름이 내용을 못 나타내면 `--title 제목`.
   글이면 표준 입력으로: `python3 <이 스킬 폴더>/scripts/inbox.py add --stdin --title 제목 --topic <주제> --facts <핵심 사실> --source <출처> <<'끝' … 끝`
   이미 `raw/` 에 있으면 `--raw raw/파일`.
   - **결론이면**(대화나 기존 노트에서 나온 결론 · 비교 · 분석) 질문(받지 못했으면 뺀다) · 결론 · 근거(근거 노트 `[[링크]]` · 원자료 경로) · 날짜를 글로 적어 `--stdin --conclusion --source 대화` 로 저장한다. 대기 줄의 출처가 `결론 · 대화` 가 되고, 2단계가 `synthesis/` 에 넣는다.
   - **고칠 말이면**(틀린 내용 바로잡기) 무엇이 어떻게 틀렸고 맞는 것은 무엇인지 글로 저장한다(규칙 1). 노트를 직접 고치지 않는다.
   프로그램이 raw 저장(같은 이름은 `-2`, 그림은 `raw/assets/`) · 대기 한 줄 · 그 파일들만 커밋까지 한다. **raw 는 그 뒤로 고치지 않는다.** `wiki/inbox.md` 를 손으로 고치지 않는다.

### 2단계 노트 쓰기 — 뒷단

1. `Agent` 도구로 `knowledge-base:ingester` 를 **백그라운드로**(`run_in_background: true`) 띄운다. 프롬프트는 「지식베이스 대기 자료를 노트로 써 줘」 한 줄이면 된다 — 에이전트가 대기 목록에서 읽는다. `model` 은 넘기지 않는다 — 쓰는 사람의 기본 설정 모델로 돌게. 다른 ingester 가 이미 돌고 있어도 띄운다. 겹치면 뒤의 것이 알아서 그냥 끝난다.
2. 사람에게는 한두 줄만: 저장한 자료 · 핵심 · 「노트는 뒤에서 쓸게요」. 그리고 대화를 이어 간다. 에이전트를 기다리지 않는다.
3. 끝났다는 알림이 오면 보고를 두세 줄로 전한다: 만든 · 고친 노트, 사람이 볼 어긋남, 이유를 물을 것(`**왜:** 확인 안 됨`).

**그 자리에서 하는 경우:** 내가 이미 에이전트나 예약 실행이거나, `Agent` 도구가 없거나, 다른 플러그인이 「정리까지」를 줬을 때. 그때는 `<이 스킬 폴더>/references/ingest.md` 를 읽고 처음부터 끝까지 한다. 묻지 않는다.

## query — 찾기

1. **`wiki` 를 보기 전에** `python3 <이 스킬 폴더>/scripts/inbox.py list` 로 대기 목록을 먼저 읽는다. 주제 · 핵심 사실이 걸리면 그 raw 를 읽는다(PDF · 사진도 직접 읽는다).
2. 필요한 만큼만 내려간다. 전체를 읽지 않는다. `wiki/index.md` 로 노트를 고르고 → 폴더로 묶인 것은 `ls` 로 그 폴더의 파일 이름을 본다(내용은 읽지 않는다) → 이름으로 모자라면 대표 노트 → 해당 노트. 그래도 모자라면 `grep -ril` 로 더 찾고, 노트에 없으면 `raw/` 까지 내려간다.
3. 근거 노트(`[[링크]]` 또는 파일 경로)를 붙여 답한다. **대기 자료를 근거로 쓰면 「정리 전 자료」라고 표시한다.** 지식베이스에 없으면 없다고 말한다.
4. 답이 다시 쓸 만한 비교 · 분석 · 결론이면 「지식베이스에 저장할까요?」 한 줄로 묻는다(사람이 없으면 묻지 않는다). 예라고 하면 그 결론을 ingest 한다(1단계 결론 저장 → 2단계 뒷단).
5. `log.md` 에 `## [오늘] query | 질문 한 줄`. 이어지는 작업이 있으면 그 커밋에 함께, 찾기만 했으면 `log.md` 만 커밋.

## lint — 점검

ingest 2단계가 끝나면 이어서 돈다. 사람이 「지식베이스 점검해」라고 해도 같다.

1. `python3 <이 스킬 폴더>/scripts/lint.py --fix` — 링크를 `[[파일-이름|보일 이름]]` 모양으로 맞추고(표기만 다른 끊긴 링크 · 보일 이름 없이 하이픈이 보이는 링크), 끊긴 링크 · 아무도 가리키지 않는 노트 · index 에 빠진 노트(폴더로 묶인 것은 대표 노트만 본다) · 이름이 겹치는 노트 · index 에 머리가 없는 폴더 · 60줄을 넘는 대표 노트 · 띄어쓰기 든 파일 이름 · 폴더 밖의 파일 · 노트 없는 폴더 · 대기와 raw 가 어긋나는 것을 찾는다.
2. **기계적인 것은 묻지 않고 고친다:** index 에 빠진 노트 · 폴더 머리를 더하고, 띄어쓰기 든 파일 이름을 하이픈으로 바꾸고 링크도 고친다.
3. **내용은 고치지 않고 표시만 한다.** ingest 에 이어서 돌 때는 이번에 건드린 노트와 그 노트가 링크한 노트만, 건드린 노트가 없으면 이 단계를 건너뛴다. 사람이 점검을 시키면 전체를 본다. AI가 직접 본다: 노트끼리 어긋나는 말, 새 자료가 이미 뒤집은 옛 주장, 자주 나오는데 노트가 없는 이름 · 개념, 이어야 하는데 안 이어진 링크, 비어 있는 곳과 다음에 찾아볼 질문. 어긋나는 노트에는 `> 어긋남: …` 으로 남기고, 어느 것이 맞는지는 사람이 판단한다. 대기와 raw 가 어긋난 것, 이름이 겹치는 노트, 긴 대표 노트도 고치지 않고 보고한다. 긴 대표 노트는 다음 ingest 가 나눈다. 노트를 지우거나 합치지 않는다.
4. `log.md` 에 `## [오늘] lint | 찾은 것 n개 · 고친 것 n개` → 커밋.
5. 표로 보고한다. 사람이 판단할 것을 맨 위에.

## 커밋

```
python3 <이 스킬 폴더>/scripts/commit.py -m "<ingest|query|lint>: 한 줄" <바꾼 파일들>
```

raw 저장과 노트 쓰기의 커밋은 `inbox.py` 가 하고, 그 밖의 작업은 이 명령으로 한다. 지식베이스 기준 경로의 파일을 하나씩 적는다(폴더 안 됨). 세션이 겹쳐도 적은 파일만 커밋되고, lock 과 이름 · 이메일은 프로그램이 처리한다. 기록 저장소가 없으면 「기록 저장소 없음」으로 끝나니 보고에 그 한 줄을 넣는다. `git add` · `git commit` 을 직접 치지 않는다. 푸시하지 않는다 — 원격 저장소는 사람이 정한다.

## 다른 플러그인에서 부를 때

이 스킬이 다른 플러그인의 **유일한 입구**다. 부르는 쪽은 `Skill` 도구로 `knowledge-base:kb` 를 부르고, 아래를 인자로 준다. 지식베이스 위치 · 규칙 · 파일 이름 · index · log · 커밋은 이 스킬이 정하고, 부르는 쪽에는 알려 주지 않는다. 노트는 `wiki/…` 기준으로만 말하고, `settings.py` 출력이나 지식베이스 위치가 드러나는 경로는 돌려주지 않는다.

| 작업 | 주는 것 | 돌려주는 것 |
|---|---|---|
| ingest | 내용(글 또는 파일 경로) · 출처 · (선택) 결론이라는 표시 · 「정리까지」 · 폴더 · 노트 이름 희망 · 노트 틀 | 저장한 raw · 커밋 해시 또는 「기록 저장소 없음」, 정리까지 했으면 만든 노트 · 고친 노트 · 만든 폴더 · 어긋난 곳 |
| query | 질문 | 답 · 근거 노트(대기 자료면 「정리 전 자료」), 없으면 없다고 |

- ingest 는 1단계 raw 저장을 하고 2단계는 뒷단에 맡긴 채 돌아간다. **「정리까지」나 폴더 · 노트 희망 · 노트 틀을 받으면** 노트 틀은 대기에 남겨 둘 수 없으니 그 자리에서 2단계까지 한다. 부르는 쪽이 지식베이스의 노트를 바로 읽어야 하면 「정리까지」를 준다.
- lint 는 공개 작업이 아니다. 다른 플러그인의 요청으로 돌리지 않는다.
- **폴더 · 노트 이름은 희망이다.** 규칙에 어긋나지 않으면 따르고, 다르게 정했으면 보고에 적는다.
- **노트 틀은 부르는 쪽이 갖고 온다.** 받으면 머리말 아래 본문을 그 모양대로 쓰되 머리말 · 근거 · 링크 · 어긋남 규칙은 지식베이스 규칙을 따른다. 틀을 이 플러그인이나 규칙에 저장하지 않는다.
- 사람이 없으면 묻지 않고 끝까지 간다. 지우기 · 합치기가 필요하면 하지 않고 보고한다.
