# kb — 내 지식베이스

> `<이 스킬 폴더>` = 이 스킬을 불렀을 때 받은 Base directory.
> 명령의 `python3` 이 없다고 나오면(윈도우) `python` 으로, 그것도 없으면 `py -3` 으로 바꿔 친다.

**어떤 작업이든 먼저** `python3 <이 스킬 폴더>/scripts/settings.py show` 로 지식베이스 위치(`kb`)와 규칙 파일(`rules`)을 확인하고, **그 규칙 파일을 읽고 따른다.** 지식베이스 안에 `rules.md` 가 있으면 그것이 규칙이고, 없으면 이 스킬의 기본 규칙이다. 칸 · 이름 · 링크 · 노트 모양 · 지키는 선이 다 거기 있다. 사람과 이야기할 때는 「위키」 대신 「지식베이스」.

| 말 | 작업 |
|---|---|
| 「지식베이스 만들어 줘」 · 처음 쓸 때(지식베이스 폴더가 없을 때) | 처음 만들기 |
| 「지식베이스에 넣어 줘」 · 「이 파일 넣어 줘」 · 「이 결론 저장해 줘」 | Ingest |
| 「지식베이스에서 찾아 줘」 · 「예전에 ~ 어떻게 했지」 | Query |
| 「지식베이스 점검해」 | Lint |

## 처음 만들기

1. `python3 <이 스킬 폴더>/scripts/init.py` — 내 설정의 위치(기본 `~/knowledge-base`, 윈도우는 `C:\Users\내이름\knowledge-base`)에 `rules.md` · `raw/` · `wiki/` 와 시작 칸 · `index.md` · `log.md` 를 만든다. 사람이 다른 곳을 말하면 `init.py <폴더>`(설정도 그 폴더로 바뀐다). 이미 있는 파일은 건드리지 않는다.
2. 만든 폴더 구조를 ├── └── 그림으로 보여 주고, 「이제 『지식베이스에 넣어 줘』로 자료를 넣으면 돼요」 한 줄.
3. 옵시디언으로 보고 싶다고 하면: 옵시디언에서 「폴더를 보관함으로 열기」로 지식베이스 폴더를 고르게 안내한다.

## Ingest — 넣기

먼저 자료가 어디서 왔는지 본다. **대화나 기존 노트에서 나온 결론이면 `raw/` 에 넣지 않고 아래 「결론 넣기」로 간다.** 바깥에서 온 자료(파일 · 붙여 넣은 글 · 회의 기록 · 사람이 알려 준 사실)는 이어서 1번부터.

1. 원자료를 `raw/` 에 둔다. 파일이면 복사(이름은 하이픈, 이름이 내용을 못 나타내면 `YYYY-MM-DD-제목` 으로), 회의 · 대화 기록이나 붙여 넣은 글이면 `raw/YYYY-MM-DD-제목.md` 로 저장(첫 줄에 어디서 온 것인지 · 날짜). 같은 이름이 이미 있으면 끝에 `-2` · `-3`. 이미 `raw/` 에 있으면 그대로. **raw 는 그 뒤로 고치지 않는다.**
2. 끝까지 읽고, 핵심 몇 줄을 사람에게 짧게 말한다. 답을 기다리지 않고 바로 이어 간다(무엇을 강조할지 사람이 말하면 그때 따른다). 사람이 없으면(에이전트 · 예약 작업) 그 몇 줄을 마지막 보고에 넣는다.
3. 걸리는 쪽을 찾는다 — `wiki/index.md` 를 먼저 읽고 `grep -ril` 로 이름 · 낱말을 찾는다. 있으면 **고치고**, 없으면 맞는 칸에 **새로 만든다**(규칙 2). 맞는 칸이 없으면 규칙대로 새 칸을 만든다(규칙 2). 고치거나 만든 쪽 머리의 `sources` 에 이 원자료를 더한다. 복사한 파일이라 raw 에 출처를 못 적으면 쪽 본문 맨 위에 `출처: …` 한 줄. 원자료 하나가 여러 쪽(고객 · 프로젝트 · 브랜드 · 주제 …)을 건드리는 게 보통이다.
4. 원자료 요약 쪽이 필요하면 `topics/` 에(짧게, 근거 = raw 경로).
5. 이어지는 쪽끼리 `[[파일-이름|보일 이름]]` 링크. 어긋나는 옛 내용은 「어긋남」으로 남긴다.
6. `wiki/index.md` 고치기 → `wiki/log.md` 에 `## [오늘] ingest | 원자료 제목` + 건드린 쪽 → 바꾼 파일만 커밋.
7. 보고: 만든 쪽 · 고친 쪽 · 만든 칸 · 어긋난 곳 · 커밋.

### 결론 넣기 (「좋은 답은 다시 넣는다」)

1. 대화에서 나온 결론 · 비교 · 분석을 `wiki/synthesis/제목.md` 새 파일로. 질문(받지 못했으면 뺀다) · 결론 · 근거(근거 노트 `[[링크]]` · 원자료 경로) · 날짜. 머리의 `sources` 에는 근거 노트 · 원자료를 적는다. 정해지지 않은 건 「검토 중」.
2. 근거 쪽들에 `관련 결론: [[제목|…]]` 한 줄을 더한다.
3. 결론이 고객 · 프로젝트 · 브랜드의 지금 상태를 바꾸면 그 쪽도 고친다.
4. index · log(`## [오늘] ingest | 결론: 제목`) → 바꾼 파일만 커밋.
5. 보고는 위 7번과 같다.

## Query — 찾기

1. `wiki/index.md` 로 쪽을 고르고, 모자라면 `grep -ril` 로 더 찾는다. 그 쪽들을 읽는다. 위키에 없으면 `raw/` 까지 내려간다.
2. 근거 쪽(`[[링크]]` 또는 파일 경로)을 붙여 답한다. 지식베이스에 없으면 없다고 말한다.
3. 답이 다시 쓸 만한 비교 · 분석 · 결론이면 「지식베이스에 저장할까요?」 한 줄로 묻는다(사람이 없으면 묻지 않는다).
4. `log.md` 에 `## [오늘] query | 질문 한 줄`. 이어지는 작업이 있으면 그 커밋에 함께, 찾기만 했으면 `log.md` 만 커밋.

## Lint — 점검

1. `python3 <이 스킬 폴더>/scripts/lint.py` — 끊긴 링크 · 아무도 가리키지 않는 쪽 · index 에 빠진 쪽 · index 에 머리가 없는 칸 · 띄어쓰기 든 파일 이름 · 칸 밖의 파일 · 노트 없는 폴더를 찾는다.
2. 그다음 AI가 직접 본다: 쪽끼리 어긋나는 말, 새 자료가 이미 뒤집은 옛 주장, 자주 나오는데 쪽이 없는 이름 · 개념, 이어야 하는데 안 이어진 링크, 비어 있는 곳(검색으로 채울 만한 것)과 다음에 찾아볼 질문.
3. 표로 보고하고, **고칠지는 묻고** 고친다(쪽을 지우거나 합치는 건 꼭 먼저 묻는다).
4. `log.md` 에 `## [오늘] lint | 찾은 것 n개 · 고친 것 n개` → 커밋.

## 커밋

```
python3 <이 스킬 폴더>/scripts/commit.py -m "<ingest|query|lint>: 한 줄" <바꾼 파일들>
```

지식베이스 기준 경로의 파일을 하나씩 적는다(폴더 안 됨). 세션이 겹쳐도 적은 파일만 커밋되고, lock 과 이름 · 이메일은 프로그램이 처리한다. 기록 저장소가 없으면 「기록 저장소 없음」으로 끝나니 보고에 그 한 줄을 넣는다. `git add` · `git commit` 을 직접 치지 않는다. 푸시하지 않는다 — 원격 저장소는 사람이 정한다.

## 다른 플러그인에서 부를 때

이 스킬이 다른 플러그인의 **유일한 입구**다. 부르는 쪽은 `Skill` 도구로 `knowledge-base:kb` 를 부르고, 아래를 인자로 준다. 지식베이스 위치 · 규칙 · 파일 이름 · index · log · 커밋은 이 스킬이 정하고, 부르는 쪽에는 알려 주지 않는다. 쪽은 `wiki/…` 기준으로만 말하고, `settings.py` 출력이나 지식베이스 위치가 드러나는 경로는 돌려주지 않는다.

| 작업 | 주는 것 | 돌려주는 것 |
|---|---|---|
| 넣기 | 내용(글 또는 파일 경로) · 출처 · (선택) 칸 · 쪽 이름 희망 · 쪽 틀. 결론이면 그렇다고 밝히고 결론 · 근거 · 날짜 · (선택) 질문 | 만든 쪽 · 고친 쪽 · 만든 칸 · 어긋난 곳 · 커밋 해시 또는 「기록 저장소 없음」 |
| 찾기 | 질문 | 답 · 근거 쪽, 없으면 없다고 |

- 점검은 공개 작업이 아니다. 다른 플러그인의 요청으로 돌리지 않는다.
- **칸 · 쪽 이름은 희망이다.** 규칙에 어긋나지 않으면 따르고, 다르게 정했으면 보고에 적는다.
- **쪽 틀은 부르는 쪽이 갖고 온다.** 받으면 머리말 아래 본문을 그 모양대로 쓰되 머리말 · 근거 · 링크 · 어긋남 규칙은 지식베이스 규칙을 따른다. 틀을 이 플러그인이나 규칙에 저장하지 않는다.
- 사람이 없으면 묻지 않고 끝까지 간다. 지우기 · 합치기가 필요하면 하지 않고 보고한다.
