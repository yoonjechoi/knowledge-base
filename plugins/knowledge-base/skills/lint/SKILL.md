# lint — 점검

> `<스킬 폴더>` = 이 스킬을 불렀을 때 받은 Base directory. 도우미는 `python3 <스킬 폴더>/../../scripts/wiki.py`(윈도우에서 `python3` 이 없으면 `python`, 그것도 없으면 `py -3`).
> **먼저** `wiki.py where` 로 위치를 보고, 지식베이스 폴더의 `CLAUDE.md`(schema)를 읽고 따른다. 사람에게는 「지식베이스」라고 한다.

지식베이스가 커져도 건강하게 유지하려고 가끔 돌린다. 사람이 지식베이스를 버리는 이유는 장부 정리가 가치보다 빨리 늘어서다 — 그 정리를 LLM 이 한다.

1. `wiki/index.md` · `wiki/overview.md` · `wiki/log.md` 의 최근 기록을 읽고, 페이지들을 훑는다. 페이지가 많으면 `grep` 으로 링크(`[[`)와 머리(`updated` · `sources`)를 먼저 모은다.
2. **찾는 것**
   - 페이지끼리 어긋나는 말
   - 새 자료가 이미 뒤집은 낡은 주장(오래된 `updated` 와 새 원자료를 견준다)
   - 아무도 가리키지 않는 외톨이 페이지
   - 여러 페이지에 나오는데 자기 페이지가 없는 중요한 개념 · 개체
   - 이어야 하는데 안 이어진 링크, 끊긴 링크, index 에 빠진 페이지
   - 웹 검색으로 채울 수 있는 빈 곳
   - 아직 ingest 하지 않은 원자료(`wiki.py pending`)
3. **고친다 — 장부 일은 묻지 않고:** 빠진 링크 · 끊긴 링크 · index 에 빠진 줄을 고친다. 어긋나는 말은 지우지 않고 양쪽에 `> 어긋남:` 을 남긴다. 어느 것이 맞는지는 사람이 정한다.
4. **제안한다 — 사람에게 묻고:**
   - 페이지가 없는 중요한 개념 → 「페이지를 만들까요?」
   - 빈 곳 → 웹 검색으로 채울 자료 후보(제목 · 주소). 사람이 고르면 그 자료를 ingest 한다(raw 를 거친다).
   - 새로 조사할 질문 · 새로 찾아볼 자료 몇 개.
   - 밀린 원자료가 있으면 「넣을까요?」
5. **log** — `wiki/log.md` 맨 아래에 `## [오늘] lint | 찾은 것 n개 · 고친 것 n개` → 바꾼 파일만 커밋(`wiki.py commit -m "lint: …" <파일들>`). git 이 없으면 건너뛴다.
6. **보고** — 표 하나. 사람이 정할 것(어긋남 · 만들 페이지 · 채울 빈 곳)을 맨 위에, 고친 것은 아래에 한 줄씩.

페이지를 지우거나 합치지는 않는다. 그게 낫겠으면 제안만 한다.
